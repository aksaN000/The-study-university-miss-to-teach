\theading{A course concept, refreshed}{the box the audience rule promises}

\begin{refresher}{CSE321}{Processes}
A process is a running program plus everything the operating system keeps about it: an address
space, open files, an environment, a current directory, and a process ID. Two runs of the same
program are two processes that share nothing but the file they started from.
\end{refresher}

\theading{The history first}{because every tool was somebody's fix}

\begin{backintime}{1971}
Early Unix found programs by looking in a short, fixed list of directories. When more places
were needed, the list became a variable that every user could change, and the search order
became the user's responsibility. That variable is the one we still type today.
\end{backintime}

\theading{Mechanisms as figures}{two processes, one boundary}

When the shell runs a program it does not become the program. It asks the kernel for a copy of
itself, and the copy replaces its own contents with the program we named.
Figure~\ref{fig:demo-forkexec} shows the conversation.

\theading{When the steps matter}{an algorithm, numbered}

\begin{algo}{How the shell turns a name into a program}
procedure resolve(name)
  if name contains "/" then return name     // a path: no search at all
  for each dir in PATH, left to right do
    if dir/name exists and is executable then
      return dir/name                        // first match wins
  fail "command not found"
\end{algo}

\theading{Myths, retired}{a belief, then what really happens}

\begin{myth}{Installing a program makes it available everywhere.}
Installing puts files somewhere. Whether a name finds them depends on \texttt{PATH}, which is
different per shell, per user, and per environment.
\end{myth}

\begin{breakage}
We put an empty directory first in \texttt{PATH} and a fake \texttt{python} inside it. The
next \texttt{python} ran our fake. Removing the directory from \texttt{PATH} brought the real
one back, and \texttt{type python} showed us which one was winning at every step.
\end{breakage}
